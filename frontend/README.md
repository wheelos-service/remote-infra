# 运维平台前端

当前界面以 `frontend_bak/` 为视觉基准，使用原有侧栏、卡片、表格和工作台风格。
导航分为车队总览、车辆监控、远程驾驶、告警中心和任务管理。
任务页保留原列表、详情和新建表单，明确为 Mock 预览，保存与下发不开放。
首页默认接入八车动态 Mock：地图渲染真实地图几何，车辆统计/列表/详情/HUD、
Monitor 健康状态和告警均读取同一份合成快照。视频仍为示例图片，未接入真实流。
页面明确标为 Mock，未知字段不填造正常值，不挂载真实账号或控制能力。
后续实时接口与模拟控制模块仍保留，但未接入当前默认页面，不能据此宣称三端链路已连接。

## 车队总览：统计口径与位置展示

界面/数据接入基线提交为 `a149195`，后续按各模块职责逐步优化，不改变整体视觉风格。
总览不再用一个综合状态反推驾驶模式或将异常车辆数冒充告警事件数。

| 字段 | 当前口径 | 真实链路的权威来源 |
| --- | --- | --- |
| 在线车辆 | 服务端最近接收 ≤ 10 秒，并持续加上浏览器等待时间 | 认证设备 `POST /api/vehicles/{id}/state` 的服务端接收时间；不是视频连接或硬件心跳 |
| 自动驾驶模式 | 在线、新鲜底盘且 `COMPLETE_AUTO_DRIVE`，停车/故障不改变该模式计数 | `apollo::canbus::Chassis.driving_mode`，通常 `/apollo/canbus/chassis` |
| 人工驾驶模式 | 在线、新鲜底盘且 `COMPLETE_MANUAL` | 同上；不说明车内/远程、不识别接管人，也不证明一次接管转换 |
| 部分自动/紧急/未知 | `AUTO_STEER_ONLY`/`AUTO_SPEED_ONLY`、`EMERGENCY_MODE`、缺失/过期分别显示 | 同上；模式不合并到自动/人工计数 |
| 待恢复告警 | 当前保留窗口内按车辆/故障键/发生周期聚合，尚无明确恢复的数量，含恢复状态待确认 | Data SDK 从 Monitor 生成的 raised/changed/recovered；不是完整历史总数，缺恢复记录不可推断当前活动故障全量 |
| 健康与质量 | 底盘错误码/错误掩码、Monitor 全部检查项及紧急停车要求；缺失/过期/截断为未知 | Chassis 与 `apollo::monitor::SystemStatus`；Monitor topic 必须配置 `system_status_channel`，不猜默认主题 |
| 定位 | 原始米制 X/Y、heading_rad、frame 与源年龄 | `LocalizationEstimate`，通常 `/apollo/localization/pose`；frame 不同、越界或缺失不叠加 |
| 远程占用 | 独立展示无会话/本人/其他终端/未知 | Gateway 的控制租约与交接栅栏，非 Chassis，也不代表执行器动作 |

遥测样本新鲜度上限为 5 秒；Monitor 面板为 3 秒且不能截断，和在线 10 秒是独立门槛。
各主题可配置，以上通常名称仅来自当前示例配置。当前页面仍是 Mock，不是已连接真实 Cyber。

“位置展示”以小字显示地图名称，采用无地理投影的 +Y 向上/+X 向右、等比例坐标与米制比例尺。
车体箭头描述车身航向，不把倒挡解释为车头翻转。车辆坐标锚点不为避让而偏移；
标签优先选中车辆并做有限避让，密集点可从列表选中，不伪造车辆间距。
离线/定位过期显示最后已知位置和虚线，不插值伪造实时运动；无有效坐标不绘制。
单击地图只改变选中目标；点击右侧车辆列表同时定位该车，即使重复点击同一车辆也重新定位。
无有效位置时仍可选车，但不移动地图；旧位置仍保留过期/离线标识。
显式“查看车辆详情”才跳页，不申请任何观看/控制租约。
默认相机稳定，不随遥测自动跳动，不提供跟随。放大/缩小/适配全图图标位于地图右下角。
左上角“图层”设置默认收起，展开后可独立切换中心线、车辆标签和网格，不触发地图平移。
选中车辆保留最多 60 个新鲜样本轨迹，
切车/换流/大幅跳变清空，不解释为完整回放或未来规划线。
搜索与全部/需关注/离线筛选同时作用于地图和列表，但不改变全车队指标；健康不是单个绿灯结论。

### 后续优先级建议

1. **先打通可信来源（P0）**：把同一读模型接到授权 Gateway；展示数据源、接收年龄、
   源年龄、模式、健康、定位质量和远程占用。请求失败应保留“旧快照”但明确不可用；
   当前“离线”尚未细分设备断联与平台读取失败，真实接入时需单列“平台不可达”。
2. **不要用人工模式冒充接管（P0）**：真正的“接管中/已接管/已交还”需要车端
   arbiter/控制权状态、模式转换时间、session/revision/receiver 绑定与明确设备回执；
   远程申请已受理、Room 已连、APPLIED 模拟反馈均不能替代物理交接证据。
3. **完善告警权威聚合（P0）**：总览需要服务端按 fault_key 维护的活动故障计数、
   最高严重度、开始/最近变化时间、人工知悉与设备恢复两套状态。当前窗口计数不可当作全量；
   底盘错误、低 SOC、定位停更与 Monitor 告警应分类并按来源解释，避免重复计数。
4. **值守扫描效率（P1）**：卡片显示明确分母/未知数量；颜色表示严重度，文字表示模式，
   不让“绿色自动驾驶”掩盖故障。列表增加按严重度/离线时长/SOC 排序、快捷筛选和收藏车；
   选中卡展示速度、挡位、SOC、地图版本、源年龄、占用，原始 stream/sequence 放诊断区。
5. **地图可读性（P1）**：保持道路低对比、目标高对比，选中高亮、非选中轻量化；
   小车队用方向标记/标签避让，大车队用按屏幕密度聚合、缩放后展开及服务端范围筛选。
   当前只有有限标签避让，没有聚类；不要添加大图标或随机偏移掩盖实际重叠。
6. **地图调试能力（P1）**：补充道路/车道 ID、坐标点击复制、坐标/距离测量、边界类型、
   地图/定位 frame 检查、轨迹跳变原因。地图必须提供经过验证的原点/投影/版本元数据；
   后续底图转换与实车坐标对齐另行验收，不能从数量级猜经纬度。
7. **未来图层（P2）**：仅在车端契约具备时添加规划线、障碍物、占用网格、任务路线/围栏；
   每层独立来源/频率/时间戳和开关，不能把车道中心线标成规划轨迹。默认总览不自动开视频。
8. **工程验收（P1/P2）**：用 8/50/200 台逐级测量刷新耗时、主线程、内存和标签密度；
   测试离线/旧源/未来时间/换流/不同地图/重叠位置/缩放/筛选/窗口变化及键盘选车。
   大规模再评估虚拟列表、服务端分页与 Canvas/WebGL；当前八车 SVG 不等于规模认证。

设计采用高精地图与运营车队常见的“道路/目标/标签分层、稳定视口、列表定位、
异常优先、渐进披露”模式，不宣称复刻某一产品或完成行业对标验收。

## 告警事件中心：按车辆查看与处置

采用“运营看板 / 车辆处置 / 历史记录”三个板块，侧栏首次进入默认看板。
总览告警入口直接进入车辆处置，不强制经过看板。一辆车一行，按未恢复优先、
最高当前严重度、车辆编号稳定排序。
同车各项告警保留自己的故障键与设备恢复状态，聚合不是共同根因的判定。
总览“待恢复告警”与中心共用 `vehicle-alerts.ts` 读模型，不将记录条数当作故障数量。
看板分为当前状态与时段统计：当前状态含告警车辆、待恢复告警和严重告警车辆，
点击进入相应车辆队列；时段支持今日、滚动近7天、自定义，显示浏览器时区与明确起止时间。
新增按明确 raised 起点、恢复按明确 recovered 时间统计，并分别计算车辆数和发生周期数；
结束时间不能晚于当前时间，非法范围显示错误而非零统计。当前状态不受时段影响。
“待验证处置”和“完成处置车次”因无人工流程显示“暂未接入”，不把自动恢复当作人工处理成果。
看板统计仅限已加载记录，不是完整日报，不添加无数据依据的趋势、处理效率或报表下载。

- 相同事件 ID 去重；同一故障的触发/变化作为同一发生周期的时间线。
  明确恢复后再次触发形成新的周期；缺触发起点标注历史不完整，不虚构持续时长。
  相同时间既触发又恢复且缺排序依据时标“恢复状态待确认”，仍纳入待恢复数。
- 知悉不等于恢复，设备恢复不等于人工结案。设备离线不删除未恢复记录，
  页面明确提示不能确认当前设备状态。无权威处置单时不展示“未认领/处理中”等伪状态。
- 支持车辆编号/名称、事件编号、故障键与内容搜索；车辆、恢复状态、严重度、
  “已加载记录/近24小时有变化”联合筛选。24小时按事件发生时间过滤，不依赖固定标题。
  按已恢复事件编号搜索需选择全部状态；命中会选中所属发生周期并高亮该事件。
- 搜索不代表服务端全局检索；当前每车最多加载 100 条最近事件，更早记录可能不在范围内。
  数据窗口缩减不是设备恢复证据，生产全量活动故障需服务端权威聚合，不能仅靠该窗口。
- 点击总览告警卡进入待恢复队列；选中车“查看告警”锁定车辆。
  中心仅保留“车辆详情”，不再提供地图位置入口；侧栏返回中心保留板块、搜索、
  筛选与显式选中项（当前页面会话内，刷新不保留）。选中车因恢复离开筛选结果时不自动换成另一辆车。
- 车辆工作区默认全车时间线，覆盖该车已加载的全部故障键和发生周期，包含已恢复记录，
  不因队列搜索/恢复/严重度筛选而截断上下文。人工知悉按实际知悉时间独立排序；
  可显式切换单项范围、设备/人工类型和时间顺序。默认最早在前，实时追加不自动滚动，
  新增记录以提示按钮展示；事件编号搜索高亮并定位匹配事件。相同时间不暗示因果先后。
- 告警明细默认收起，责任人/协作人/处置进度在车辆标题区展示“暂未接入”，不是“未分配”。
  移除整排不可用操作，只保留简短说明，不伪造人员、权限、保存成功或跨用户同步。
- 历史记录按告警发生周期列表展示，支持现有搜索与筛选、查看过程返回车辆工作区。
  正式报表与导出留待完整历史和服务端处置记录接入后实现，当前没有完整日报导出。

演示补充 `sim-004` 同车两项告警（Monitor 严重故障、电量警告），5 秒后追加故障变化，
不增加待恢复数。`sim-006` 在 20 秒后明确恢复：初始共 2 辆/3 项待恢复，
恢复后 1 辆/2 项，中心与总览同步变化。

尚未实现服务端协同处置：需要独立的车辆处置单、单一负责人和多协作人、检查项/备注、
待认领→处理中→待验证→完成流程、并发版本控制、权限与审计、完整历史分页及全量活动告警。
当前只有事件知悉 API，不应借它伪造上述流程，也不提供前端本地假协同。
超时升级、值班路由与通知抑制同样需后续服务端能力，协作权限必须与车辆控制权分离。

## 车辆监控：列表与单车详情

车辆监控只保留车辆列表，支持按编号/名称搜索、筛选有告警或离线车辆。
点击车辆直接进入详情，返回列表保留搜索、筛选和滚动位置，不提供多车监看和回放入口。
详情只提供“实时 / 健康状态 / 车辆信息”三个页签。
车辆列表告警摘要和详情顶部“查看告警”直接进入唯一的告警中心并限定本车、展示全部状态；
详情不再重复展示告警时间线。从告警中心进入车辆详情时，可通过“返回告警处置”回到原上下文，
保留板块、筛选、选中车辆、时间线配置和滚动位置（当前页面会话内）。

- **实时**：前视相机为主要区域；目前明确标识为示例图片，未接入实时视频。
  点击画面进入同车接管工作台的监看模式，不自动申请控制权。
  局部 BEV 使用当前地图的米制车道数据，车辆居中、车头向上，支持 30/60/120 米等比例范围。
  定位过期或离线时保留最后位置并停止跟随；坐标系不匹配、位置无效或朝向未知时不猜测位置。
  地图车道只是参考，不代表已接入车道匹配、规划轨迹或周边目标。
- **健康状态**：按异常优先展示已有底盘、定位、连接及 Monitor 检查结果和数据更新时间。
  缺失、过期、截断或未知状态不显示为正常；没有主动远程诊断执行入口。
- **车辆信息**：展示已有编号、名称、车型、软件和地图版本及资料更新时间；硬件配置和维护资料尚未接入。

## 远程驾驶：先选车再进入工作台

侧栏“远程驾驶”始终先进入独立车辆列表，支持车辆编号/名称搜索和离线筛选。
列表显示连接、驾驶模式、远程会话及视频状态，点击整行直接进入该车工作台，无需额外操作按钮；
车辆编号按钮同时支持键盘进入。使用与总览/监控一致的 `overviewVehicle` 读模型。
遥测在线不等于网络质量优秀或视频可用；当前视频明确标为未接入，网络质量未知、未测量。
任务管理保留独立入口，单车详情不重复提供任务页签。
任务列表和指标明确标为技术查询，不将查询成功包装为运营任务完成；新建表单只用于布局预览。

进入工作台后，顶部固定显示车辆编号、监看状态、远程占用和返回列表入口。
工作台绑定独立的车辆 ID，不随总览/监控选车而改变；目标车辆不存在时明确报错，不切换到第一辆车。
从监控相机进入时直接绑定该车，不必重复选车；返回远程驾驶列表保留其自己的搜索、筛选和滚动位置。
工作台地图复用等比例、车头向上的局部 BEV，定位过期或离线冻结并标记最后位置。
全屏仍显示目标车辆编号；进入、切车、退出全屏均不会申请控制权或发送车辆命令。
当前仅为 Mock 监看布局，不连接真实视频、控制会话或执行器。

运行跨页面流程验收前，先启动上述 Mock 前端并准备地图，安装环境需提供 Google Chrome 和 Node：

```bash
FRONTEND_URL=http://localhost:8000/ node scripts/test-operations-ui.mjs
```

可通过 `CHROME_BIN` 指定 Chrome 可执行文件。该脚本检查告警唯一工作区、处置上下文返回、
独立远程选车、列表状态保留、离线地图、全屏车辆身份及窄屏布局，阻止 API 和外部资源请求。

`base_map.txt` 的中心线和边界采样点保持原始米制坐标，不混入 `editor_map.json`
局部点位，不猜测经纬度。演示 frame 为 `map:{目录名}`，不匹配的定位不会叠加。
车辆只在各自选定车道末端循环，不是路网导航、物理仿真或真实路线规划。

此模式无需账号/设备凭据，只请求同源 `maps/*.json`，不调用 Gateway/OAuth/LiveKit，
不申请观看或控制租约；即使同时指定控制开关也不能发令。视频仍为原版外部示例图片，
不模拟解码视频或证明三端链路。`preview`/`scenario` 参数不再切换当前首页数据源。
动态八车页不混入兼容 `/operations` 的固定历史样例，不提供真实回放。
事件确认和任务创建全部禁用，不能将 Mock 的健康/恢复视为真实车辆结论。

生成的 `public/maps/` 和构建产物不进 Git；生产构建会复制已准备的地图到 `dist/maps/`，
开发服务会读取已复制到 `dist` 的资源，重新转换后需重启开发服务或重新构建。
部署前确认地图发布权限，勿将内部地图随普通前端包公开发布。
功能清单、测试矩阵与三端联调见 [`docs/remote-validation.md`](../docs/remote-validation.md)。

## 模拟控制测试

以下及后续实时接口章节为保留模块的参考，不是当前备份布局首页的可用入口。

默认 `simulationControl: false`。在公开运行配置中设为 true，或 localhost 使用
`?dev=1&control=simulation`，即可在选定操作目标后打开模拟控制面板。
前提是 Gateway 仅对废弃/模拟车辆 ID 配置 `SIMULATED_CONTROL_VEHICLES_JSON`，
且对应 C++ SDK 设定 `control_mode=simulation`。WebCrypto 要求 localhost 或 HTTPS。
前端开关不授予控制权：服务端白名单、ACL 和单操作员单车仲裁始终生效。

申请后等待车端反馈 READY；按住模拟前进按钮发令，松开回到中立 setpoint。
失焦/隐藏、断线/重连、续期/反馈失败停止发令且不自动恢复。
必须释放并等待**模拟交接**完成，才能切换下一辆车。
APPLIED 仅表示模拟器接受，不能证明实车执行或物理交接。
`?preview=1` 始终不发送请求或指令。

自动跨端验收：在仓库根执行 `python3 tests/control-chain.py`；
构建前提和协议见 [SDK 指南](../apps/vehicle-edge-cpp/README.md#testable-v2-control-loop)。

## 公开运行配置

默认 Gateway、LiveKit、Casdoor 地址和 Casdoor client ID 沿用旧 `apps/operator-console/` 的配置。部署环境可在 `index.html` 加载 `main.js` 之前注入公开配置，例如：

```html
<script>
  window.__LIVEKIT_INFRA_CONFIG__ = {
    gatewayUrl: 'https://gateway.example.com',
    livekitUrl: 'wss://rtc.example.com',
    authorizeUrl: 'https://sso.example.com/login/oauth/authorize',
    tokenUrl: 'https://sso.example.com/api/login/oauth/access_token',
    clientId: 'public-operator-client-id'
  }
</script>
```

这些字段只允许公开端点和 OIDC client ID；不要放置 client secret、LiveKit API secret、设备凭据或访问令牌。Gateway 必须允许平台 origin 的 CORS，Casdoor 必须登记与平台 origin/path 完全匹配的 redirect URI，生产环境使用 HTTPS/WSS。

Access token 只保存在当前页面内存中。刷新页面需要重新登录；浏览器不会恢复之前的车辆连接。

## 车辆实时遥测

正常模式下，“车队总览”和“车辆监控”通过已登录账号的访问令牌读取 Gateway 的授权车辆目录
(`/api/vehicles`)，每 2 秒顺序轮询一次；目录失败时保留上次快照供参考，但显示离线并报告错误。
车辆详情显示源样本新鲜度、浏览器接收时长、服务端/源时间戳和时钟异常，不会把未知样本标为正常。
车辆操作占用状态只反映会话占用，不代表当前车辆输入动作。坐标按遥测 frame 显示为局部米制坐标，
不会擅自投影为地理地图。查看车队或详情不会连接 LiveKit 或发送控制指令。

`?preview=1` 启用固定预览场景。车辆、诊断、告警、任务及历史预览通过与实时接口相同的 Zod schema
校验，并明确标识为非实时；预览模式跳过 OAuth 回调校验、Gateway 请求、观看租约和 LiveKit 连接。
预览数据不能满足真实车辆的驾驶就绪条件。

通过 `?preview=1&scenario=reverse` 切换固定数据场景；支持 `default`、`parking`、
`reverse`、`stale`、`missing`、`clock`、`error`、`recovered`、`history` 和
`mission-unknown`。同一场景用于车辆摘要与业务详情，分别保留过期、未知、故障恢复、
历史缺口及任务结果未知语义；所有场景仍禁止真实网络和指令。`default` 保留原双车样例。
未知场景名显式报错，不静默回退。跨端验证入口为根目录
`bash tests/platform-contract.sh`，依赖和验证范围见 `tests/README.md`。

真实只读监看需操作者显式添加车辆面板；每个面板先申请独立 viewing 租约，再创建独立 LiveKit
Room，最多同时四辆车。关闭一个面板仅清理它自己的 Room 和租约。离开工作台或退出账号会清理全部面板；
导航离开前会提示。占用信息只来自授权目录；请求失败或数据过期时显示未知，不代表车辆当前输入动作。
每次连接尝试使用独立 UUID v4 请求 ID，同一页面挂载使用同一 client instance ID；不同标签页不会复用控制身份。
租约响应严格校验车辆、会话和有效期限，剩余时间扣除完整 HTTP 往返时延；续期串行执行，
请求在 5 秒内超时。续期失败或租约到期立即停止监看并释放租约，连接失败、取消、账号切换和
卸载也会用原始登录令牌释放。取消后迟到的申请成功响应同样释放，不会创建 Room。
释放失败会显示错误或在卸载时输出不含凭据的控制台错误；关闭页面等无法保证 HTTP 完成的情况
依赖停止续期后的 30 秒 TTL 回收，不保证卸载释放请求送达。申请超时不自动重试，结果不确定时
也由 TTL 回收。仅接受身份严格匹配 `vehicle-{vehicle_id}` 的车辆视频。
C++ 已有可选原生 SDK 与显式合成相机闭环，真实相机接入和部署验收尚未完成；
租约或信令连接成功不代表视频已就绪，不会开放控制或驾驶指令。

目录请求禁用浏览器缓存并在 8 秒后超时重试。年龄以单调时钟的请求开始时间计，
保守地包含完整 HTTP 往返时延；回调年龄加上快照/发布的最大存储与传输年龄。
在线状态按服务端车辆接收时间继续老化，目录失败或超过有效期的操作占用状态显示未知。

### 诊断、告警、Mission 与历史

车辆详情、告警及任务页接入 `GET /api/vehicles/{vehicle_id}/data`，每 2 秒串行轮询，
请求和响应体总计最多 8 秒。账号/车辆切换取消旧请求，不展示其他身份的缓存。
接口可达和 Monitor 源数据新鲜度分别显示；源未知/过期/未来/截断均不作为当前健康结论。
`?preview=1` 使用同一严格契约的固定数据，所有变更按钮关闭且不发起请求。

- Monitor 面板展示各检查项、HMI、其他组件及紧急停车要求，仅作为状态，不是控制命令。
- 告警页展示 Monitor raised/changed/recovered；控制角色且有车辆 control ACL 时，
  可确认“已知悉”，但不会关闭故障或伪造设备恢复。
- 任务页区分云端落库、设备接收、dispatch fence、unknown 对账及终态。
  只允许为 `mission_query` 车辆创建携带原请求身份的只读账本查询；
  SDK 仍独立校验能力/地图/期限。查询成功不等于原运动任务完成。
- POST 超时/断网显示“结果未知”，本页面保留原始载荷供同身份重试；
  轮询确认相同请求已落库后解除重试状态。清除本地重试不取消云端任务；
  离开前保存待核实 ID，浏览器不持久保存请求或凭据。
- 容量卡展示云端事件/任务与设备 outbox/inbox/故障键保留量、待传/待对账量；
  达到 80% 显示告警。未收到或老旧的设备诊断不能推断无积压。
- 导出按有界游标获取全部保留事件或任务，所有页通过验证后才生成 NDJSON；
  不删除记录或去重身份。结果与人工确认逐页变化，导出不是 SQLite 一致性备份。

#### 兼容遥测读区

车辆详情保留的兼容读区对当前选中的一辆授权车辆轮询
`GET /api/vehicles/{vehicle_id}/operations`，间隔 10 秒，超时 8 秒，使用当前会话的 Bearer
令牌、请求取消和 `no-store`。请求错误、无数据或未实现的持久化来源会显示不可用/未知，不回退到实时模拟值；
该兼容读区不提供写操作；告警确认与只读查询由上方 `/data` 面板提供。

兼容诊断仅描述已采集底盘和定位遥测的接收/年龄及相关问题，不能代表完整车端 `SystemStatus` 或整体健康。
历史接口最多返回 300 条最新样本；前端明确标为有界抽样而非完整回放，并按 `stream_id` 与 `sequence`
标记流切换、缺口或序号异常。地图只显示局部米制坐标，不作经纬度解释或地理投影。驾驶、地理投影和
Mission 命令能力保持 false。

## 本地只读联调

### 合入 Cyber 验证功能后的边界

工作台已支持前后三路视角（`camera-left/center/right` 与
`camera-rear-left/rear-center/rear-right`）、单前视兼容、手动切换及中间放大。
自动视角跟随模拟前后意图，目录中有源时间且新鲜的挡位可辅助确认；旧前进挡不会覆盖
尚未确认的倒车意图。未知/过期挡位不猜测方向；停车保留当前视角。
仅挂接当前组视频，保留 `adaptiveStream`；不宣称隐藏轨道即停止车端上行。
轨道已订阅不等于帧新鲜，各视频块另显示解码/停止状态。

显式启用 `simulationControl` 后，v2 模拟面板可使用键盘、按住按钮和标准手柄，
复用 `apps/operator-console/src/lib/` 的纯输入状态机；经 `simulation-input.ts`
转换为 -1000..1000 整数并走现有签名/授权/反馈链路，不导入 v1 传输或执行器。
手柄需确认标准映射、启用后松键回中，再按住 LB；左 X 转向、右 Y 前后、B 模拟制动。
目前只开放标准映射，不适配不满足该映射的设备。失焦/隐藏释放会话；换输入、编辑、
断手柄及采样超时停止并需重新使能。组件卸载移除监听器/定时器。
1–4/E/Q 和挡位/模式手柄按钮未接入 v2，明确拒绝，不降级到旧协议。
这些功能仅验证模拟控制，不开放实车驾驶或自动驾驶/遥控模式仲裁。

仅查看平台/接管页面布局（不登录、不调用 Gateway/LiveKit）：

```text
http://<前端主机>:8000/?preview=1
```

此预览模式可从车辆列表选择车辆并打开工作台预览，但显示的是占位画面；不会尝试真实接管。

在本机使用 Gateway 的开发认证模式时，可运行前端开发服务器并访问：

```text
http://localhost:8000/?dev=1&backend=http://localhost:8080&livekit=ws://localhost:7880
```

进入“只读监看”页后可使用“本地开发登录”提示输入开发令牌，并通过 Gateway `/api/auth/me` 校验。该入口只在 `localhost`、`127.0.0.1` 或 `::1` 且显式带 `dev=1` 时出现；令牌不会写入 URL 或浏览器存储。

预览模式的车辆与业务记录均为固定界面样例，不代表已注册车辆、实时告警、任务或健康结果。正常模式从当前账号授权目录选择车辆，服务端 ACL、车辆是否运行以及视频是否发布仍需分别确认。

当前平台工作台为只读监看。原 `apps/operator-console/` 作为独立旧入口保留，其开发控制流程见 `docs/local-dev.md`；执行控制联调仅限隔离的模拟器/测试台，首次验证不得连接真实行驶车辆。

前端不实现远程控制切车或驾驶权转移，不把 HTTP 释放受理视为车辆确认，也不推断目标车已可控。后端控制释放确认在物理 handover 策略验证前保持关闭；面板关闭只结束该浏览器观看租约与 Room。

工作台可将授权列表中的任意一辆车设为唯一“操作目标”，与多车监看面板独立；
切换这个目标不会申请控制租约或更换任何 Room。界面分别显示操作目标与当前工作台
控制车辆（当前驾驶未开放）。后续控制协调器必须绑定唯一会话，而不是跟随下拉框或
最近收到的车辆状态；从 A 控制切换 B 仍须先释放 A 并取得权威交接确认。
