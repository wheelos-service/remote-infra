# 运维平台前端

当前界面保留原视觉原型的侧栏、卡片、表格和工作台风格；`frontend/` 是唯一平台源码目录。
导航分为车队总览、车辆监控、远程驾驶、告警中心和任务管理。
默认 `/#/` 复用统一组织运营平台；任务调度引擎未实现，明确不可执行，
但任务页仍显示本组织车辆只读目录。查看者/管理员可监看，操作员仅在显式操作范围内控制。
所有有效可信组织成员默认可读本组织全部有效车辆及实时视频，自动涵盖新增车辆；
`操作车辆范围` 默认 none 表示无操作权限，不再限制读取，查看者即使 all 也不能控制。
组织管理页仅提供“返回运营平台”和退出登录，共享登录及组织选择；不提供独立旧路由。
显式开发 `?preview=1`（hash 外）接入八车动态 Mock：地图渲染真实地图几何，车辆统计/列表/详情/HUD、
Monitor 健康状态和告警均读取同一份合成快照。视频仍为示例图片，未接入真实流。
页面明确标为 Mock，未知字段不填造正常值，不挂载真实账号或控制能力。
Mock 与真实账号隔离；统一平台 `/#/?page=drive` 接入授权车辆、
C++ 三路视频与 v2 模拟控制。Mock 不会因此连接真实车辆。

## 部署边界

本次发布由同一台服务器上的 Compose Nginx 与 Caddy 提供网页和 HTTPS 入口。
操作员只需浏览器，不需要在每台电脑安装前端。部署及证书配置见
[局域网安装指南](../docs/setup.md)；独立静态托管不属于本次发布流程。

## 导航与后续工作

后端前置条件及尚未完成的协作告警、远程驾驶数据接入事项见
[前端后续路线图](../.agents/knowledge/frontend-optimization-roadmap.md)。
页面、车辆、总览/监控/驾驶列表搜索与筛选、告警板块和筛选写入 HashRouter 地址，
例如 `/#/?page=drive&driveVehicle=sim-004`；支持分享、刷新恢复与浏览器前进/后退。
搜索输入替换当前历史，页面跳转新增历史；同一次操作的车辆和页面变更合并为一次跳转。
外层 `?map=...` 仍用于选择地图。未知页面/筛选参数明确报错，目标车不存在时不自动换车。
滚动位置、时间线展开/排序和未提交表单仅为当前页面会话状态，不通过链接分享或保证刷新恢复；
地址不保存令牌、权限、控制租约或真实控制状态。

## 车队总览：统计口径与位置展示

界面/数据接入基线提交为 `a149195`，后续按各模块职责逐步优化，不改变整体视觉风格。
总览不再用一个综合状态反推驾驶模式或将异常车辆数冒充告警事件数。

| 字段 | 当前口径 | 真实链路的权威来源 |
| --- | --- | --- |
| 在线车辆 | 服务端最近接收 ≤ 10 秒，并持续加上浏览器等待时间 | 认证设备 `POST /api/vehicles/{id}/state` 的服务端接收时间；不是视频连接或硬件心跳 |
| 自动驾驶模式 | 在线、新鲜底盘且 `COMPLETE_AUTO_DRIVE`，停车/故障不改变该模式计数 | `apollo::canbus::Chassis.driving_mode`，通常 `/apollo/canbus/chassis` |
| 人工驾驶模式 | 在线、新鲜底盘且 `COMPLETE_MANUAL` | 同上；不说明车内/远程、不识别接管人，也不证明一次接管转换 |
| 部分自动/紧急/未知 | `AUTO_STEER_ONLY`/`AUTO_SPEED_ONLY`、`EMERGENCY_MODE`、缺失/过期分别显示 | 同上；模式不合并到自动/人工计数 |
| 待恢复告警 | 当前保留窗口内按车辆/故障键/发生周期聚合，尚无明确恢复的数量，含恢复状态待确认 | Data SDK 从 Monitor 生成的 raised/changed/recovered；不是完整历史总数，缺恢复记录不可推断当前活动故障全量 |
| 健康与质量 | 底盘错误码/错误掩码、Monitor 全部检查项及紧急停车要求；缺失/过期/截断为未知 | Chassis 与 `apollo::monitor::SystemStatus`；Monitor topic 必须配置 `system_status_channel`，不猜默认主题 |
| 定位 | 原始米制 X/Y、heading_rad、frame 与源年龄 | `LocalizationEstimate`，通常 `/apollo/localization/pose`；frame 不同、越界或缺失不叠加 |
| 远程占用 | 独立展示无会话/本人/其他终端/未知 | Gateway 的控制租约与交接栅栏，非 Chassis，也不代表执行器动作 |

遥测样本新鲜度上限为 5 秒；Monitor 面板为 3 秒且不能截断，和在线 10 秒是独立门槛。
各主题可配置，以上通常名称仅来自当前示例配置。Mock 页面不连接真实 Cyber；
默认统一平台的数据可信度取决于获授权的设备上报，不能仅凭页面显示认定实车接入成功。

“位置展示”以小字显示地图名称，采用无地理投影的 +Y 向上/+X 向右、等比例坐标与米制比例尺。
车体箭头描述车身航向，不把倒挡解释为车头翻转。车辆坐标锚点不为避让而偏移；
标签优先选中车辆并做有限避让，密集点可从列表选中，不伪造车辆间距。
离线/定位过期显示最后已知位置和虚线，不插值伪造实时运动；无有效坐标不绘制。
单击地图只改变选中目标；点击右侧车辆列表同时定位该车，即使重复点击同一车辆也重新定位。
无有效位置时仍可选车，但不移动地图；旧位置仍保留过期/离线标识。
显式“查看车辆详情”才跳页，不申请任何观看/控制租约。
默认相机稳定，不随遥测自动跳动，不提供跟随。放大/缩小/适配全图图标位于地图右下角。
左上角“图层”设置默认收起，展开后可独立切换中心线、车辆标签和网格，不触发地图平移。
选中车辆保留最多 60 个新鲜样本轨迹，
切车/换流/大幅跳变清空，不解释为完整回放或未来规划线。
搜索与全部/需关注/离线筛选同时作用于地图和列表，但不改变全车队指标；健康不是单个绿灯结论。

### 后续优先级建议

1. **先打通可信来源（P0）**：把同一读模型接到授权 Gateway；展示数据源、接收年龄、
   源年龄、模式、健康、定位质量和远程占用。请求失败应保留“旧快照”但明确不可用；
   当前“离线”尚未细分设备断联与平台读取失败，真实接入时需单列“平台不可达”。
2. **不要用人工模式冒充接管（P0）**：真正的“接管中/已接管/已交还”需要车端
   arbiter/控制权状态、模式转换时间、session/revision/receiver 绑定与明确设备回执；
   远程申请已受理、Room 已连、APPLIED 模拟反馈均不能替代物理交接证据。
3. **完善告警权威聚合（P0）**：总览需要服务端按 fault_key 维护的活动故障计数、
   最高严重度、开始/最近变化时间、人工知悉与设备恢复两套状态。当前窗口计数不可当作全量；
   底盘错误、低 SOC、定位停更与 Monitor 告警应分类并按来源解释，避免重复计数。
4. **值守扫描效率（P1）**：卡片显示明确分母/未知数量；颜色表示严重度，文字表示模式，
   不让“绿色自动驾驶”掩盖故障。列表增加按严重度/离线时长/SOC 排序、快捷筛选和收藏车；
   选中卡展示速度、挡位、SOC、地图版本、源年龄、占用，原始 stream/sequence 放诊断区。
5. **地图可读性（P1）**：保持道路低对比、目标高对比，选中高亮、非选中轻量化；
   小车队用方向标记/标签避让，大车队用按屏幕密度聚合、缩放后展开及服务端范围筛选。
   当前只有有限标签避让，没有聚类；不要添加大图标或随机偏移掩盖实际重叠。
6. **地图调试能力（P1）**：补充道路/车道 ID、坐标点击复制、坐标/距离测量、边界类型、
   地图/定位 frame 检查、轨迹跳变原因。地图必须提供经过验证的原点/投影/版本元数据；
   后续底图转换与实车坐标对齐另行验收，不能从数量级猜经纬度。
7. **未来图层（P2）**：仅在车端契约具备时添加规划线、障碍物、占用网格、任务路线/围栏；
   每层独立来源/频率/时间戳和开关，不能把车道中心线标成规划轨迹。默认总览不自动开视频。
8. **工程验收（P1/P2）**：用 8/50/200 台逐级测量刷新耗时、主线程、内存和标签密度；
   测试离线/旧源/未来时间/换流/不同地图/重叠位置/缩放/筛选/窗口变化及键盘选车。
   大规模再评估虚拟列表、服务端分页与 Canvas/WebGL；当前八车 SVG 不等于规模认证。

设计采用高精地图与运营车队常见的“道路/目标/标签分层、稳定视口、列表定位、
异常优先、渐进披露”模式，不宣称复刻某一产品或完成行业对标验收。

## 告警事件中心：按车辆查看与处置

采用“运营看板 / 车辆处置 / 历史记录”三个板块，侧栏首次进入默认看板。
总览告警入口直接进入车辆处置，不强制经过看板。一辆车一行，按未恢复优先、
最高当前严重度、车辆编号稳定排序。
同车各项告警保留自己的故障键与设备恢复状态，聚合不是共同根因的判定。
总览“待恢复告警”与中心共用 `vehicle-alerts.ts` 读模型，不将记录条数当作故障数量。
看板分为当前状态与时段统计：当前状态含告警车辆、待恢复告警和严重告警车辆，
点击进入相应车辆队列；时段支持今日、滚动近7天、自定义，显示浏览器时区与明确起止时间。
新增按明确 raised 起点、恢复按明确 recovered 时间统计，并分别计算车辆数和发生周期数；
结束时间不能晚于当前时间，非法范围显示错误而非零统计。当前状态不受时段影响。
“待验证处置”和“完成处置车次”因无人工流程显示“暂未接入”，不把自动恢复当作人工处理成果。
看板统计仅限已加载记录，不是完整日报，不添加无数据依据的趋势、处理效率或报表下载。

- 相同事件 ID 去重；同一故障的触发/变化作为同一发生周期的时间线。
  明确恢复后再次触发形成新的周期；缺触发起点标注历史不完整，不虚构持续时长。
  相同时间既触发又恢复且缺排序依据时标“恢复状态待确认”，仍纳入待恢复数。
- 知悉不等于恢复，设备恢复不等于人工结案。设备离线不删除未恢复记录，
  页面明确提示不能确认当前设备状态。无权威处置单时不展示“未认领/处理中”等伪状态。
- 支持车辆编号/名称、事件编号、故障键与内容搜索；车辆、恢复状态、严重度、
  “已加载记录/近24小时有变化”联合筛选。24小时按事件发生时间过滤，不依赖固定标题。
  按已恢复事件编号搜索需选择全部状态；命中会选中所属发生周期并高亮该事件。
- 搜索不代表服务端全局检索；当前每车最多加载 100 条最近事件，更早记录可能不在范围内。
  数据窗口缩减不是设备恢复证据，生产全量活动故障需服务端权威聚合，不能仅靠该窗口。
- 点击总览告警卡进入待恢复队列；选中车“查看告警”锁定车辆。
  中心仅保留“车辆详情”，不再提供地图位置入口；侧栏返回中心保留板块、搜索、
  筛选与显式选中项（当前页面会话内，刷新不保留）。选中车因恢复离开筛选结果时不自动换成另一辆车。
- 车辆工作区默认全车时间线，覆盖该车已加载的全部故障键和发生周期，包含已恢复记录，
  不因队列搜索/恢复/严重度筛选而截断上下文。人工知悉按实际知悉时间独立排序；
  可显式切换单项范围、设备/人工类型和时间顺序。默认最早在前，实时追加不自动滚动，
  新增记录以提示按钮展示；事件编号搜索高亮并定位匹配事件。相同时间不暗示因果先后。
- 告警明细默认收起，责任人/协作人/处置进度在车辆标题区展示“暂未接入”，不是“未分配”。
  移除整排不可用操作，只保留简短说明，不伪造人员、权限、保存成功或跨用户同步。
- 历史记录按告警发生周期列表展示，支持现有搜索与筛选、查看过程返回车辆工作区。
  正式报表与导出留待完整历史和服务端处置记录接入后实现，当前没有完整日报导出。

演示补充 `sim-004` 同车两项告警（Monitor 严重故障、电量警告），5 秒后追加故障变化，
不增加待恢复数。`sim-006` 在 20 秒后明确恢复：初始共 2 辆/3 项待恢复，
恢复后 1 辆/2 项，中心与总览同步变化。

尚未实现服务端协同处置：需要独立的车辆处置单、单一负责人和多协作人、检查项/备注、
待认领→处理中→待验证→完成流程、并发版本控制、权限与审计、完整历史分页及全量活动告警。
当前只有事件知悉 API，不应借它伪造上述流程，也不提供前端本地假协同。
超时升级、值班路由与通知抑制同样需后续服务端能力，协作权限必须与车辆控制权分离。

## 车辆监控：列表与单车详情

车辆监控只保留车辆列表，支持按编号/名称搜索、筛选有告警或离线车辆。
点击车辆直接进入详情，返回列表保留搜索、筛选和滚动位置，不提供多车监看和回放入口。
详情只提供“实时 / 健康状态 / 车辆信息”三个页签。
车辆列表告警摘要和详情顶部“查看告警”直接进入唯一的告警中心并限定本车、展示全部状态；
详情不再重复展示告警时间线。从告警中心进入车辆详情时，可通过“返回告警处置”回到原上下文，
保留板块、筛选、选中车辆、时间线配置和滚动位置（当前页面会话内）。

- **实时**：前视相机为主要区域；目前明确标识为示例图片，未接入实时视频。
  点击画面进入同车接管工作台的监看模式，不自动申请控制权。
  局部 BEV 使用当前地图的米制车道数据，车辆居中、车头向上，支持 30/60/120 米等比例范围。
  定位过期或离线时保留最后位置并停止跟随；坐标系不匹配、位置无效或朝向未知时不猜测位置。
  地图车道只是参考，不代表已接入车道匹配、规划轨迹或周边目标。
- **健康状态**：按异常优先展示已有底盘、定位、连接及 Monitor 检查结果和数据更新时间。
  缺失、过期、截断或未知状态不显示为正常；没有主动远程诊断执行入口。
- **车辆信息**：展示已有编号、名称、车型、软件和地图版本及资料更新时间；硬件配置和维护资料尚未接入。

## 远程驾驶：先选车再进入工作台

本节 Mock 行为仅适用于 `?preview=1`；默认统一平台使用授权车辆与实时视频，
参见下方“当前路由与数据边界”，不再提供单独的 `/teleop` 路由。

侧栏“远程驾驶”始终先进入独立车辆列表，支持车辆编号/名称搜索和离线筛选。
列表显示连接、驾驶模式、远程会话及视频状态，点击整行直接进入该车工作台，无需额外操作按钮；
车辆编号按钮同时支持键盘进入。使用与总览/监控一致的 `overviewVehicle` 读模型。
遥测在线不等于网络质量优秀或视频可用；当前视频明确标为未接入，网络质量未知、未测量。
任务管理保留独立入口，单车详情不重复提供任务页签。
任务列表和指标明确标为技术查询，不将查询成功包装为运营任务完成；新建表单只用于布局预览。
任务页默认展示列表和详情，点击“新建任务”展开表单，可再次收起；表单不保存、不下发。

进入工作台后，顶部固定显示车辆编号、监看状态、远程占用和返回列表入口。
工作台绑定独立的车辆 ID，不随总览/监控选车而改变；目标车辆不存在时明确报错，不切换到第一辆车。
从监控相机进入时直接绑定该车，不必重复选车；返回远程驾驶列表保留其自己的搜索、筛选和滚动位置。
工作台地图复用等比例、车头向上的局部 BEV，定位过期或离线冻结并标记最后位置。
工作台改为前左、前中、前右三路独立占位，不再用前/后示例图片冒充相机。
全屏仍显示目标车辆编号；进入、切车、退出全屏均不会申请控制权或发送车辆命令。
当前仅为 Mock 监看布局，不连接真实视频、控制会话或执行器。

## 当前路由与数据边界

`App.tsx` 只注册统一运营平台 `/` 和组织管理 `/admin`。
默认首页登录后获取组织上下文及授权车辆；没有数据时不回退 Mock。
只有 hash 外 `?preview=1` 使用本地八车 Mock，任务演示表单的保存与下发保持禁用。

`/#/?page=drive` 使用 Gateway 授权车辆目录，操作者显式选车后工作台申请观看。工作台只订阅
`camera-left`、`camera-center`、`camera-right` 三路前视视频；未开放后视相机或旧的多车监看页面。
每一路都必须持续产生解码帧才视为视频就绪。v2 控制默认关闭；仅在部署显式启用
`simulationControl` 时提供模拟输入，不能连接实车执行器。身份、签名、反馈、超时和交接门槛
仍按既有协议执行。

统一平台使用 hash 查询参数切换总览、监控、驾驶、告警和任务；没有独立
`/teleop`、`/data`、`/operations` 兼容入口。`VehicleDataPanel` 只由固定预览测试挂载。
部署配置、容器挂载与运行时配置以 [部署文档](../docs/deploy-from-source.md) 为准；本 README 不复制多车、
多相机或已移除页面的旧运行说明。

## 本地开发与验证

启动 `npm run dev` 后，纯 Mock 使用 `/?preview=1`，不会调用 Gateway 或 LiveKit。
本地真实服务与模拟控制使用：

```text
http://localhost:8000/?dev=1&control=simulation&backend=http://localhost:8080&livekit=ws://localhost:7880#/?page=drive
```

本机开发令牌登录只在 `localhost`、`127.0.0.1` 或 `::1` 且带 `dev=1` 时提供；令牌仅保存在
当前页面内存。摄像头就绪前控制输入保持锁定，失焦、断线、视频停更或控制反馈异常都会停止
并锁定输入，不能仅凭再次出帧自动恢复。控制验收只使用 C++ 模拟车辆，不连接实车执行器。

进入工作台不申请控制权；点击“申请模拟控制权”、等待 READY、显式启用输入后才发令。
`control-session-client.ts` 负责申请/续租/签名/停发/释放与交接，
`control-input-adapter.ts` 只把共享输入意图转换为 v2 命令，不处理认证或执行。
申请控制权返回 HTTP 409 时，界面区分控制权已占用与上一次交接未确认，并保持
`idle` 供用户手动重试；不会自动抢占或清除交接保护。先在原浏览器释放控制权，
等待车端确认后再申请。同一操作员的其他车辆会话也可能阻止申请。网络超时等结果
不确定的失败，以及已获得会话后的安全故障，仍保持锁定并要求释放。
签名和发布完成时立即复查 250 ms 预算与租约/反馈期限；被新输入替换的签名不计入待确认命令。
实际发出的最早待确认命令超过 450 ms 未获确认会锁定控制，重复反馈不能延长该期限。
首次故障会断开控制 RTC，并在释放过程中保留原始原因；交接清理错误单独显示。
“导出近期控制时序诊断”下载最近 128 条本地时序事件，包含签名/发布耗时、命令确认 RTT、
待确认数量和本地时钟变化，不包含令牌、签名包或控制值。这些数据不代表单向命令年龄或画面年龄；
v2 仍使用可靠传输，完整的新鲜度协议待跨端实现，见[发布限制](../docs/compatibility.md)。历史评审保留在本地开发资料中。
这两个模块不再保留旧 `simulation-*` 文件或导出别名；模拟语义保留在 UI 和车端执行配置。
验证命令见 [测试指南](../tests/README.md)，当前发布限制见 [兼容性说明](../docs/compatibility.md)。

键盘及标准手柄输入状态机由 `packages/teleop-shared` 提供，供 React 前端多个模块复用。
跨端模拟控制和真实浏览器三路解码
验收脚本分别见 `python3 tests/control-chain.py` 与 `python3 tests/driving-ui.py`；
部署配置、运行时注入及生产 Compose 流程见 [部署文档](../docs/deploy-from-source.md)。
